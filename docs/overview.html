1. 目的 — なぜ「単位」なのか

物理が苦手な生徒の多くは、公式を文字列として暗記していて、必要な場面で取り出せません。 一方で物理を使える人は、公式を忘れても 「速さを出したいのだから m/s、つまり距離を時間で割ればいい」 と、単位から式の形を復元します。

これが次元解析です。実際に強力な技術で、物理を専門にする人は日常的に使っています。 にもかかわらず、学校ではほとんど訓練されません。公式は覚えさせられますが、 「N は kg·m/s² だから、これを m² で割れば圧力 Pa になる」という組み立ての練習はまず行われない。 ここが空白地帯です。

本作の目的は、この次元解析の感覚を、説明ではなく操作の反復で身につけさせることです。 そのために、次元解析の各要素をゲームのルールに一対一で対応させました。

次元解析でやっていることゲームのルール
単位を掛ける／割る道に浮かぶ ×m ÷s の球を通る
同じ単位が約分されて消える相殺。球が縮み、金のリングと高音のアルペジオが鳴る
求めたい量の単位に一致させるEXIT が要求する単位にぴったり一致したときだけ扉が開く
ルート（変形の順序）を選ぶ一度通った道は崩れて戻れない。分かれ道の選択が、そのまま演算の選択になる
条件つきの式変形関門🔒。「kg を持っている」「m を含まない」などを満たす手持ちでないと通れない
√をとる（全次数が偶数のときだけ可能）√の橋。全指数が偶数のときだけ渡れる

2. 遊び方（ルールは4行）

  1. 主人公は物理の単位を1つだけ持った半透明の球。持っている単位の量だけ球は大きくなります。
  2. 道に浮かぶ ×m ÷s の球を通ると、手持ちの単位がその演算を受けます。 同じ単位で割ると相殺して球が縮みます。
  3. 後戻りできません。一度通ったマスは崩れて穴になり、二度と通れません。
  4. EXIT が要求する単位にぴったり一致したときだけ、扉が開きます。
  5. 「もどす」は回数制限つきです（第1章5回・第2章3回・第3章2回）。 使い切っても「やり直し」は何度でもできます。
この作品の設計上の核心は「後戻りできない」ことです。
掛け算は順番を入れ替えても結果が同じなので、後戻りが自由だと「拾う順番」に意味がなくなり、 迷路である必然性が消えます。後戻りを禁じることで、分かれ道でどちらを選ぶかが 取り返しのつかない「どの演算を使うか」の決定になり、進む前に頭の中で単位を計算する必要が生まれます。 そのため迷路はわざとループを持つ形（一本道ではない）に生成しています。一本道では経路が一意に決まり、 選択がゼロになってしまうからです。

同じ理由で、袋小路（行き止まり）を1つも作っていません。戻れない以上、何も置かれていない袋小路は 「入ったら やり直すしかない」純粋な罰で、プレイヤーが得るものがありません。迷路を生成したあと、 行き止まりのマスをすべて隣とつないで消しています。全13ステージで袋小路が0個であることは、 検証スクリプトが毎回確かめます。

そして「もどす」に回数制限を設けています。ここが無制限だと、 「適当に進んで、違ったら戻す」という総当たりでクリアできてしまい、 進む前に単位を計算するという本作の学習目標そのものが無効化されます。 掲げているルールを実際に効かせるための制限です。 ただし「やり直し」は無制限なので、使い切っても詰むことはありません。 失うのはそのステージの進捗だけで、もう一度考え直せば必ず先に進めます。

画面の見かた

  • 上段の2枚のカード … 左が「いま持っている単位」、右が「EXIT が要求する単位」。この2つを一致させるのが目標です。
  • 中央の3D迷路 … 半透明の球が単位の球。🔒が関門。緑のマスが EXIT。通った跡は灰色の穴になります。
  • 次元距離バー … EXIT の単位と、いまの単位がどれだけズレているかを表します。減っていれば正しい方向です。
  • 右上の「手数」 … かかった手数です。最短手数はプレイ中には表示しません。答えの長さが先に分かると「進む前に単位を計算する」動機が弱まるためです。クリア後に「◯手（最短◯手）」として示します。この最短手数は、アプリがその場で自動探索した実測値です（人が手で決めた数字ではありません）。

設定

  • 記憶モード … 手持ちの単位表示をぼかします。頭の中だけで単位を追う練習になります。
  • もどす回数を制限する … 既定でオンです。オフにすると「もどす」が無制限になります。
  • 効果音 … オン／オフを切り替えられます。
  • 迷路の壁の色 … 6色から選べます（見やすさの個人差に対応するため）。

4. 機能と、そこに込めた学習設計

3段階ヒント

① ゴールとの差分（何が足りず、何が多すぎるか）→ ② 残り最短手数 → ③ 次の一手、の順に開きます。 いきなり答えを出すと学習が消えるため、必ず段階を踏ませます。

もどす回数の制限 — 試行錯誤を「考える」に変える

「もどす」を無制限にすると、プレイヤーは考えずに進んで、間違えたら戻す、という 総当たりに流れます。それでもクリアはできてしまうため、学習が起きません。 そこで章ごとに回数を配り（第1章5回・第2章3回・第3章2回）、 残り回数をボタンに表示しています。先の章ほど厳しくなり、 1歩進む前に手持ちの単位を計算する必要が自然に生まれます。

一方で、これが理不尽にならないようにしています。「やり直し」は何度でも使え、 詰みは自動検出されるので、失うのは常に「そのステージ1回分」だけです。 苦手な生徒のために、設定で制限を外すこともできます。

詰みの自動検出

1手ごとに「EXIT にまだ到達できるか」「残ったマスで必要な単位を作れるか」を判定し、 不可能になった時点で知らせます。気づかないまま20手歩かせて時間を無駄にさせないためです。 失敗を安くすることで、試行錯誤の回数そのものを増やしています。

クリア直後の4択クイズと、実際の公式の提示

クリアした瞬間に F = ma → N = kg·m/s² のように、 いま自分が組み立てたものが本物の物理法則だったことを提示します。 続けて4択クイズを出し、解いた内容を言語化させます（生成効果）。

報酬の出しかたを2系統に分けている

相殺（＝単位が消える）だけを派手に演出すると、「とにかく単位を消せばよい」と誤って学習します。 実際には kg → J のように増やすのが正解の場面もあります。そこで演出を明確に分けました。

  • 相殺した … 金のリング＋高音の上昇アルペジオ（快感を担当）
  • ゴールに近づいた … 緑のリング（正しさを担当）
  • ゴールから遠ざかった … 赤土のリング

相殺と同時に近づいた場合は、低い「近づいた音」を重ねません。高音の快感を濁さないためです。

数値を入れていない理由

あえて数値を扱いません。数値を足すと計算ゲームになり、 「数字を無視してよい」という次元解析最大の強みが薄れてしまうからです。 本作で問われるのは最後まで単位だけです。

6. 技術的な特徴

外部ファイル・外部通信がゼロ

画像・音声ファイル・外部ライブラリを一切使っていません。 3D表示は Three.js などを使わず、Canvas 2D に自前で透視投影を実装しました。 効果音は音声ファイルではなく WebAudio による合成です。 結果として作品全体が HTML 1ファイル（約107KB）に収まっており、 ダブルクリックするだけで、オフラインでも、どの端末でも同じように動きます。

単位を「5次元の指数ベクトル」として扱う

すべての単位を、5つの基本次元（kg, m, s, A, K）の指数ベクトルとして表現しています。 これにより、掛け算・割り算はベクトルの加算・減算に、 「EXIT の単位と一致するか」の判定はベクトルの一致判定に帰着します。 曖昧さがゼロなので、採点が完全に自動化でき、ゲームとして破綻しません。 次元距離バーも、このベクトル間の距離をそのまま表示しています。

迷路は自動生成し、解けることを検証してから出荷している

ループを持つ迷路を生成し、正解ルート上に必要な演算と関門を配置したうえで、 「後戻り禁止」＝自己非交差経路の探索器で本当に解けることを確認してから固定データとして書き出しています。 行き止まりには単位の球を置きません（後戻りできない以上、袋小路の球は原理的に使えないため、 生成時に候補から除外し、書き出し前にも再検査しています）。 乱数のシードは固定してあるので、誰がビルドしても同じ迷路になります。

同じ探索器をアプリ内にも積んでいる

クリア後に示す最短手数、段階ヒントの「次の一手」、詰みの自動検出は、 すべてこの探索器をアプリ内で走らせて得ています。 ステージを修正しても評価がズレることがありません。
